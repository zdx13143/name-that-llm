## 已确定的实现问题

### 1. 稀疏中心化只从组内第一行扣除均值

`src/centered_stylegram.py:63` 声明按组减均值，但 `:82–86` 构造均值矩阵时，行坐标使用 `np.zeros(len(nz))`。尽管矩阵形状是 `(n_rows, n_feat)`，非零元素全部落在第0行；`block - rep` 因而只改组内第一行，其余行没有扣除均值。后续归一化不会补上缺失的中心化。

这与文件说明的算法不同，不能把原脚本输出解释为完整的 prompt 中心化实验。修复应先用小矩阵核对每行残差、组内残差和及单例处理，再进行任何真实比较；验证中须考虑代码在减均值前后还执行了归一化，不能直接对最终归一化结果要求零均值。

### 2. 当前 embedding 进入了所谓“不含新嵌入”的对照池

`src/run_embed.py:91–110` 先保存本次编码器 OOF，然后扫描全部 `oof_emb_*.npy`，将本次结果也加载进 `pool`。`:118–127` 又把该池报告为“原有融合（不含嵌入）”，并通过 `pool2["emb"] = oof_emb` 将同一结果再以别名加入。

因此该前后比较不是“旧池 vs 旧池加本次编码器”的干净消融。它还可能改变贪心搜索中同一预测的可用表示。`EXPERIMENTS.md:122`、`:157` 的历史增量不能仅凭当前脚本被视为已证实的独立编码器贡献；需要核对当时版本及 OOF，修正后按同一冻结协议重新报告。此问题不自动否定配置中的绝对融合分数，也不证明某个编码器没有作用。

## 验证局限与记录冲突

### 验证协议

- `src/centered_stylegram.py:128` 用验证集真实 `prompt_id` 的唯一数给聚类指定准确组数。虽然没有直接传入每行真实分组，但这个组数在隐藏测试并不可得，属于额外的已知分组信息。未来比较应分别报告真值组数诊断与只依赖文本的组数推断，不能混称完全模拟推理。
- 该脚本默认组数估计 `src/centered_stylegram.py:93` 使用 `round(n/18)`，仍携带每题约18条的结构假设；中心化是软操作，并不意味着其分组过程完全摆脱了这项假设。
