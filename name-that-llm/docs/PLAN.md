## 目标与前置条件

先建立可信的本地验证和可离线运行的 CPU 基线，再根据误差分析决定 GPU 投入。比赛目标为 18 类模型来源识别，主指标使用 balanced accuracy。

前置数据审计已完成：[数据清单](../data/README.md)和[全量审计](../reports/INITIAL_DATA_AUDIT.md)确认实际训练集为 2,699 条文本、150 个 prompt。未发现完全或空白归一的跨 prompt 重复；语义近重复不在本次完整性检查范围内。

## 阶段 1：数据与验证

1. 检查 schema、缺失、重复、标签分布和 prompt 覆盖，保存不含原文的审计摘要。
2. 优先按 `prompt_id` 划分训练/验证，保证同一个 prompt 不跨集合。官方 Data 页称隐藏 prompt 不在训练集内，因此随机按文本划分不能作为主验证方案。
3. 审计通过后选择可行的分组交叉验证折数；暂定 5 折，须确认每折各类覆盖充分。保存种子及 ID 到折号的映射，保证后续实验可比较。
4. TF-IDF 词表和 IDF 等变换仅在该折训练集拟合。重复文本检查若发现跨 prompt 重复，先处理泄漏风险，再冻结划分。

## 阶段 2：CPU 基线

自主实施以下小规模方案：

- 字符级与词级 TF-IDF 分别建立基线，再评估组合特征。
- 使用线性分类器，比较必要的正则化与类别权重设置；固定验证划分，限制实验数量。
- 主指标为 balanced accuracy，辅以各类 recall、混淆矩阵和折间波动；记录拟合/推理时间与内存。
- 保存配置、随机种子、输入校验值和运行版本。所有结果明确标为本地验证结果。

阶段验收：分组无交集、预处理无跨折拟合、18 类输出合法、实验可重跑，并说明目前主要混淆的模型类别。先根据这些证据提出下一步选择，不预设必须使用大模型。

## 阶段 3：Kaggle 离线流程

把已验证的预处理和模型加载流程整理为 Notebook，训练产物通过 Kaggle 可挂载输入提供。提交运行关闭互联网，读取实际测试全量数据，生成 `submission.parquet`，不固定公开样例行数。

在 Notebook 中校验输出列、ID 覆盖、唯一性、空值和合法标签；检查端到端运行在比赛 9 小时限制内。公开样例执行成功仅证明接口兼容，不能证明隐藏测试得分。Notebook 准备、运行和正式提交分开记录，不将文件生成写成已经提交。

## 阶段 4：按证据决定 GPU

若 CPU 基线的误差分析支持继续尝试，再提交小型文本编码器/分类模型的 GPU 实验方案。先确认公开模型的许可、可用性和离线依赖，再预估显存、训练时间与收益。

优先使用 Kaggle 免费 GPU。官方文档写每周额度通常为 30 小时，可能按资源浮动；用户实际可用硬件与余额尚未检查。两个比赛共享同一账户算力预算：先各安排一个有时间上限的小实验，再按验证改进和运行成本分配后续时长。启动前记录余额，结束后停止会话，避免闲置消耗。

一般 Notebook 文档列 CPU/GPU 会话最长 12 小时，但本比赛提交限制为 9 小时，采用比赛要求。此方案不启动付费资源或外部付费 API。
