Name That LLM：完整集成之后，怎样验证小改动

更新：2026-10-29。已核实的正式最佳记录仍为 R12 V1 / 363188587 的 Public Score 0.654。队友 e651 为 0.651。外部 Roman V32 为 0.660，R14 已冻结该配方，但没有保存版本或正式分数。R15 已完成本地算法入口、合成验证和原 2,159 行开发数据准入，还没有真实精度结果。

为什么这一轮固定完整集成

一个 SVC 分支提高，不代表加入几十种预测信号的完整方案也会提高。其它成员可能已经提供相同的信息，新的信号也可能改变原有正确答案。因此 R15 要固定同一份完整上游输出，只改变最后一个系数。旧 R6–R10 训练与搜索已经结束，本轮没有重复执行。

此前 Windows 阶段的详细学习记录保留在独立分支中：历史学习笔记。本分支不改写那些历史结果。

R15 想回答什么

R14 在完整融合后，用 37 个标点和排版特征微调类别分数。比如单双换行、成对引号和括号会一起出现；上游模型也可能已经利用这些信息。重复强化可能帮助识别，也可能把不确定但原本正确的答案推错，目前没有因果证据。

因此只登记一个候选：把末端排版改变量乘以 0.5。对照保持原强度 1.0，其它参数、成员和 ATLAS 覆盖保持一致。不在看到结果后再挑 0.25、0.75 或别的系数。

为什么现在还不能报提分

缺少完整集成的五折预测，以及每个训练依赖没有见过对应验证题目的证据。full-fit 模型已经用过这些题目，不能因为把预测数组命名为 OOF 就当成未见数据的预测。现有 ModernBERT/独立 SVC OOF 也不能代替完整集成。

旧 30-prompt 留出已经使用且受保护。本次在用户明确授权下读取其所在完整 CSV 一次，仅用于隔离导出原开发数据；保护区不写出、不训练、不评分，之后不再读取原 CSV。既定 120-prompt 开发范围、行序、标签顺序和 GroupKFold 折号均已按冻结哈希核验，无需重新抽样。

两种“验证通过”有什么不同

本地工程验证：15 项合成测试通过，确认原强度公式与冻结上游一致、减半只改指定项、错误折绑定和错误尺度被拒绝。这些数据都是人工构造的。

本地预测验证：必须用真实、完整且隔离正确的五折预测计算 BA、18 类召回率和按 prompt 配对区间。本轮尚未开始，真实训练、编码器前向和官方标签评分均为 0。供数阶段曾按明确授权读取完整 CSV，不能继续把保护区读取计数写成 0。

Kaggle 保存、正式提交、Public Score 和 private 结果又各是独立阶段。本轮这些新增计数全部为 0。R12 已完成的 0.654 不再称作等待出分。

一个容易忽略的尺度问题

上游 --save_lp 会把分数再除以总权重。虽然每行最大类别可能不变，分数之间的间隔会改变，排版算法的置信度门控也会改变。因此消融必须保存 _v38_before_hard 的原始尺度。R15 另外核对独立生成的原强度结果，防止输入虽合法却不代表同一基线。

当前交付与下一依赖

实际代码：CPU 重放。方案：预登记。缺失资产与最小补齐方式：完整集成 bundle 契约。实际结果：R15 报告。

后续只读查找已完成：公开的单次 LoRA24 OOF、182 文件的 nested validation cache 和 UltraBERT 五折 checkpoint 确实存在，但都未满足本轮完整 R14、原 120-prompt 划分和旧 30-prompt 排除条件。ATLAS 还明确记录使用全部 2699 条官方数据训练。没有把这些组件资产拼接后冒充完整 OOF，也没有启动评分。

源码另显示，部分融合系数和 Gaussian 温度来自上游 OOF/135-prompt 拟合。严格完整流程 OOF 还需要解决这些参数的训练范围；只重训基础模型不够。按当前成员拓扑，五个外折至少有 155 个神经 checkpoint/bundle 目标，可选 token-attention 最多另加 10 个；这是输出目标数量，实际训练任务还取决于可安全共享的阶段和内层验证。

具体证据见资产查找报告。最小重建预案先要求补齐源码、训练范围与 development-only 文本，再用最多 8 GPU-hours 试跑定标；完整重建提出 250 GPU-hours 总硬上限，必须由实测支持才可登记执行。当前没有启动这些任务，原 R15 单变量配置和停止门槛保持不变。

优先级 0 的新发现

已实际保存 S7、Instyle 和两个 token-attention 固定版本源码。源码可读不等于训练可立即重现：Instyle 把全部清洗后的外部行加进每个训练折，给 prompt ID 加 ext_ 也不能证明题目独立。EXTRA_W=0.5 仅被声明，没有用于训练权重；重建应以实际代码为准，并把修订另行登记。

恢复开发文本也有严格边界。最初的“不碰旧留出”要求不允许运行会解析完整 CSV 的旧 loader，因此先实现了只接收预先隔离导出的校验器。之后经过明确授权才执行一次隔离导出；原校验器没有放宽，新增的专用准入入口保留了真实读取记录。

严格的融合验证需要在每个外折的 96 个训练 prompts 中再做五折，用内层预测拟合系数，之后才预测外层 24 prompts。旧 155 个目标只数最终外折模型，不包括这个代价；不能把它当作完整计算预算。初始入口的 11 项人工测试及当时零读取记录见 P0 报告和来源归档。

继续查找后的实际边界

扩展查找仍未发现原 2159 行的独立文本导出；R6 包只保存模型和运行资产。新取得的 Nishant 配置确认 main.deb 是全量微调模型，与 COMP 的冻结 DeBERTa 特征头不同。标题带“两阶段 LoRA”的 V2 notebook 实际没有神经训练循环；公开数据卡写“排除相同训练文本”也不足以证明排除了同一个 prompt 的其它生成答案。

ATLAS 的嵌入配置已保存，但原 NTL trainer 仍缺失，训练清单与分发包的 model.py 哈希也不同。不能用论文仓库的 trainer 直接充当原实现。最新授权允许低负载本机 GPU；当前阻塞是合格输入和来源，不是缺少 GPU 使用许可。本机 8 GiB 显存在只读快照中已有约 4 GiB 被占用，后续必须先做短时、单任务的容量测量。本次没有训练、评分或重跑旧测试。详见继续查找报告。

真实接口必须覆盖历史标签顺序

后续发现并修复了一个输入兼容错误：R2 的身份哈希包含 gpt-first 标签顺序，而 R14 的预测列按字母排序。把两者强制设成同一个顺序，会让真实导出无法通过。现在保留原开发数据及哈希，只在拟合排版和评分前按类名转换 truth 索引。修改后的相关 28 项人工测试通过；旧夹具只使用一种顺序，未能覆盖这个接口。

登录态私有数据集检查未找到文本导出，因此准备了默认关闭的封装导出器，8 项人工测试通过后请求了准确的供数授权。该准备阶段没有真实输入或准确率证据。详见输入兼容修复。

一次授权导出已解决供数依赖

用户明确允许一次隔离导出及开发数据准入后，程序读取完整 CSV 一次、在内存中解析两遍；旧留出的 540 行因此产生 1,080 次记录解析事件，持久化、训练和评分均为 0。输出只包含原 2,159 行开发数据，字节、行身份、文本及折哈希通过独立核验。

专用准入入口先核对授权和独立审查，再读取隔离产物。最终 9 项人工测试通过，开发数据已准入至 outputs/r15_dev_export，并生成 5 个外折和 25 个内折计划。真实准入过程未再读原 CSV；各阶段训练和评分仍关闭。供数问题已解决，剩余阻塞是完整成员训练源码、外部数据逐行谱系与折排除，以及融合参数的内层拟合配置。见实际导出与准入记录。
