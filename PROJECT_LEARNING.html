2. 这个 AI 任务到底在学什么

可以把任务想成：拿到一篇英文作文，猜它是哪位“作者”写的。在这里，作者是 18 个大语言模型；prompt 是给作者的题目。

同一个题目会让不同作者使用相似的主题词。例如，大家都写“海边旅行”，就容易出现海浪、沙滩、日落。这些词主要告诉我们在写什么。我们真正想利用的是怎样写：措辞、句式、标点、表达偏好，以及更细微的组合规律。

官方训练数据共有 2,699 条、150 个 prompt。本项目已经固定：120 个 prompt、2,159 条用于开发；另外 30 个 prompt、540 条是已经使用过的旧留出，后续不再拿来训练、评分或挑方案。

这里做的是“18 类作者归属”，不是“这是不是 AI 写的”二分类。 模型必须在 18 个名字里选一个，难点经常是区分风格相近的型号。

3. 一次实验的完整流程

01提出假设
02固定验证
03生成特征
04折内拟合
05OOF 评分
06门槛决策
  1. 提出一个可检验的问题。 例如：向量里题目差异太明显，换一种建模方式能否更好地区分作者？
  2. 先固定数据与验证方式。 哪些行能用、哪些不能用、五折怎样划分，都先确定。
  3. 把文字转成数字。 模型无法直接对“文风”这个词做计算，需要把每篇文本转换成向量，也叫 embedding。
  4. 在训练折上拟合。 通过训练样本估计分类器参数；缩放、降维等需要从数据学习的步骤也只能看训练折。
  5. 对没参与该折拟合的文本预测。 收集所有折的 OOF 预测，计算总体、每折和每类指标。
  6. 按预登记门槛决定是否进入提交。 完整性、资源、输出格式与离线运行也需要通过；开发分数好不代表已经提交成功。

五折不是简单地把同一批数据训练五遍。它轮流留出五组题目：每条样本的 OOF 预测，必须来自一个没有用这条样本及同题文本拟合的分类器。

冻结编码器可以先生成全部开发文本的向量，是因为它没有用本任务数据更新参数，并且每篇文本独立编码。微调编码器时，就要按每个训练折分别训练和编码，不能沿用这套复用理由。

第四轮检验了这种监督微调方案。它像让“读文章的人”根据作者标签练习辨认风格；梯度是告诉参数应怎样小幅调整的信号，优化器执行这些调整。一个 epoch 表示该训练折的每条样本被完整用于训练一遍，本轮固定四遍。

训练日志中的 loss（损失） 衡量预测与训练标签的差距。本轮使用交叉熵：模型给真实作者的概率越低，受到的惩罚越大。损失逐步下降说明它正在适应训练样本，但也可能在记忆训练细节；只有没参与训练的题目上的预测，才能帮助我们判断是否有可迁移的识别能力。因此不能拿训练loss下降代替验证BA提升。

显存装不下很多文本时，可以用梯度累积：每次读4条，累积8批后才更新一次参数，通常相当于32条一起贡献一次更新。最后不足32条也保留，并按实际样本数计算权重。梯度检查点则通过重新计算部分中间结果换取较低显存开销，不等于额外多读一次独立样本。

本轮没有每训练完一遍就根据外层验证分数选择最好的一遍。那样验证集就参与了选择，分数容易偏乐观。我们先固定四遍，五折全部完成后统一评分；每一折都重新从同一预训练权重出发。

4. 第二轮为什么效果差：哪些是事实，哪些还只是解释

已经确认的事实

运行和产物核验通过。输入行序、标签、特征、OOF 与哈希都对得上，因此目前没有发现“评错了标签”或“缓存串了”的证据。GPU 的作用主要是加速运算，换成 GPU 并不会自动提高模型分数。

ModernBERT 在第二轮是冻结的：它以前接受过预训练，但我们没有用这 18 类作者标签修改它的内部参数。我们只在它输出的 3,072 维向量后面训练了一个逻辑回归分类头。

每折训练约 1,727/1,728 条文本，输入却有 3,072 个坐标。坐标多不等于有效信息多；它们可能重复、相关，也可能主要描述题目。这个规模需要合理约束，但“维度多”本身不能证明发生了过拟合。

截断可能丢信息，但目前不是已证实的主要原因

token 可以粗略理解为模型读文字时使用的小块，它不严格等于一个英文单词。我们固定最多读取 256 token。

开发文本中，275/2,159 条（12.7%）超过 256 token；中位数为 134，最大为 396。长文本确实有一部分没被读入，但它们现有的普通准确率为 35.3%，未截断组为 28.1%。两组的题目和作者构成不同，这不是公平的截断消融实验。

所以正确表述是：截断存在，值得知道；还不能认定它造成了主要损失。 不能为了一个看起来合理的解释就立即增加长度和训练成本。

向量里能看到明显的题目结构

把向量长度归一化后，按 prompt 分组解释的平方差比例为 30.8%，按作者标签分组为 2.59%。因为 prompt 有 120 组、作者只有 18 类，组数多的一方天然更容易解释差异，所以还要看对应的随机分组基线。

L2 归一化表示观察解释比例同组数随机基线校正后比例

按模型作者分组2.591%0.788%1.818%

这支持“题目结构很明显”的诊断，但不是因果贡献表，也不意味着向量里没有作者信息。有用信息可能在幅度较小的方向，或需要更合适的组合才能被分类器利用。

5. 第三至第六轮分别学到了什么

队友仓库的强方案参考中，有一种共享 prompt 的高斯建模思路：

一篇文本的表示 ≈ 作者风格 + 题目影响 + 剩余噪声

这是一个统计模型的假设，不是说我们已经知道每个向量坐标的真实含义。我们选了其中适合现有硬件、可复用已有向量的一部分，没有复现整个 8B/14B 强集成，也不继承它的榜单分数。

第一步：标准化，让不同坐标有可比较的尺度

可以类比“身高用厘米、体重用千克”：数字范围不同，不应只因为数值更大就得到更多重视。每折只在训练数据上计算均值和标准差，再用同一套变换处理验证数据。

第二步：从同题差异里选择 128 个方向

先在训练折中减去同题文本的均值，再做 PCA。直觉是先淡化大家共有的题目成分，再选择剩余差异中较有代表性的方向。

PCA 是一种压缩方法。这里将后续统计建模的输入从 3,072 维降到 128 维，但压缩不保证只留下作者风格，也不能按保留方差多少直接判断分类会更好。本轮保留约 86.2%–86.4% 的训练同题残差方差，只是一个变换诊断。

第三步：估计各作者的位置，以及题目和噪声怎样波动

类别均值可以想成每位作者的“常见位置”。协方差描述哪些方向波动大、哪些方向会一起变化。某个方向本来就很不稳定，那么新文本在这个方向上偏远一点，就不应被过度惩罚。

收缩（shrinkage）是在复杂的协方差估计与更保守的简单估计之间折中，减少小样本下估计不稳定的问题。它是一种正则化，不是额外取得了真实答案。

第四步：面对未知题目，仍然逐条预测

训练时允许使用训练折的 prompt_id 来学习“题目会带来怎样的变化”。验证时，分类头只接收向量，不接收真实 prompt_id；它将未知题目影响视作需要考虑的不确定性。

我们没有假设测试集每题都有 18 条，也没有强制同题必须分配出 18 个不同作者。单条、批量、倒序预测都做了一致性检查，避免一个样本因为和谁一起送进模型而被改变答案。

第四轮：让模型学习标签，为什么仍可能变差

第四轮不再冻结编码器，而是训练约1.50亿个参数。每折只有约1,727条训练文本，模型要从有限例子中学习细微的作者差异。训练loss确实逐轮下降，但最终五折BA都低于第三轮；18类中4类提升、12类下降、2类不变。例如，claude-opus-5召回提升8.333个百分点，而gpt-5.6-luna和gemini-3.7-flash各下降14.167个百分点。

这说明这套配方没有把训练改善转化为更好的跨题目识别。不能只挑某一类的提升，也不能只看训练loss，就判断方法成功。 我们同时改变了表示方式、分类头和训练方式，没有做足够的对照实验，因此还不能断定具体是数据太少、学习率不合适、欠拟合还是过拟合；更不能推广成“微调总是比冻结差”。

本轮得到的是一个清楚的排除结果：这套固定配方不进入提交。保留失败权重、预测和日志，让下一次判断有据可查；没有在同一轮看到结果后再试几个参数来寻找好看的分数。

第五轮：为什么有用的风格信息，融合后反而变弱

我们把每篇文章从四个角度转换成数字：字符片段、词片段、词形结构和功能词结构。例如，“The dragon and a kettle!”在功能词视角会变成“the CONTENT and a CONTENT !”，帮助模型关注连接方式和标点。词形视角将连续字母词替换成X/x，保留大写形态、数字和标点。它们有意淡化部分主题内容，但也可能丢失作者线索。

TF-IDF给文本片段赋权，结合一篇文章里出现的频率及它在训练文章中是否普遍。n-gram就是连续n个字符或词；LinearSVC学习若干线性打分规则，选择分数最高的作者。词表、IDF和分类器都只用当前训练折拟合，不能先看验证文本建立词表。

纯风格对照的BA为0.359325，对第三轮的增益为6.0648个百分点，描述性95%区间约[3.845,8.288]个百分点，五折都改善。这支持继续关注风格特征，但尚不能说已经超过历史全部CPU方案：当前缺少那些旧模型的完整OOF，无法作配对比较。

预登记的唯一候选是80%风格分数加20%第三轮语义分数。结果只有0.323681，比纯风格低3.5644个百分点，五折全部下降。为什么80%的权重还没让风格主导？风格模型的softmax最高分平均只有 0.0842，语义模型却是 0.4933；前者分布平，后者尖。两者虽然都加起来等于1，分数的区分幅度仍差很多。最终融合在1969/2159条上跟随语义模型的首选。

这个现象说明：归一化不等于校准，权重比例不等于决策影响比例。 Softmax把任意分数变成非负且总和1的形式，并不自动保证“0.8就意味着80%正确”。校准是检查和调整这种分数与实际正确率的关系，也必须在训练折内部完成，再交给外层未参与拟合的数据验证。

两种模型确实有互补：风格独自答对417条，语义独自答对286条。但第五轮融合纠正风格的290条错误，同时把367条原本正确的答案改错，净少77条。这是当轮已保存预测的诊断，第五轮内没有追加权重、温度或新模型搜索。第六轮据此另外预登记了一个校准方案。

第六轮：温度能改变融合，但不能偷看外层答案

温度校准的公式是 softmax(原始分数 / T)。正温度T小于1会拉开分数，T大于1会让分布更平。它不改变单个模型最高分类别，却会改变两种模型融合时的影响比例。最终开发集内部学到的风格温度约0.137，Gaussian温度约1.897；因此风格分布变尖，Gaussian分布变平。权重仍是预先固定的80/20。

温度不是手工挑出“哪个BA最好”的数字。我们在每个外层训练折里再按prompt分成三折，生成内层OOF分数，然后选择使真实标签平均负对数似然最小的正温度。外层验证题目既不能训练模型，也不能决定温度。 直接拿旧全局五折OOF的外层训练行来校准也不行，因为生成那些预测的模型可能训练过当前外层验证题目。

第六轮对较强风格对照提升1.1570个百分点，按prompt配对bootstrap的描述性95%区间为 [+0.4163,+1.8981]个百分点，五折均提升；对第三轮提升7.2218个百分点，区间为[+5.0008,+9.4001]个百分点。这支持本次校准融合进入部署验证。原120个prompt已经反复用于开发，区间不能消除多轮选模的偏差，也不保证Kaggle同样涨分。

部署还有另一个问题：训练电脑和Kaggle的软件环境可能不同。我们冻结模型文件、标签顺序和依赖，并用人工文本检查Windows/Linux的数值与批次顺序一致性。这些检查只回答“程序是否按预期计算”，不是新的准确率验证；CPU Float32与开发CUDA BF16的差异必须单独记录。

6. 怎样看懂 balanced accuracy

先理解“召回率”：某一类真实有 10 条，模型正确认出 6 条，这一类的召回率就是 6/10=60%。

普通 accuracy 把所有样本放在一起算答对比例。Balanced accuracy（BA）先分别算每一类召回率，再对各类等权平均。本项目有 18 类，所以是 18 个召回率的平均。

下面是专门用于学习的 3 类虚构例子，不是本项目实测数据：

类别真实数量答对数量召回率
A1009090%
B10440%
C10220%

普通准确率为 (90+4+2)/(100+10+10)=80%；BA 为 (90%+40%+20%)/3=50%。第一类样本多，能掩盖另外两类很差的表现；BA 让每一类都获得同等权重。

动手理解 · 虚构的 3 类示例

同样一份预测，为什么会有两个分数？

真实数量固定为 A=100、B=10、C=10。拖动答对数量，观察两种指标的不同权重。

普通 accuracy80.0%所有样本一起计数
Balanced accuracy50.0%每一类获得同等权重

accuracy = 96 / 120；BA = (90% + 40% + 20%) / 3

本项目开发集各类数量接近，因此普通准确率与 BA 常常接近。不过逐类召回仍能告诉我们：一个整体数字背后，究竟哪些作者最难认。

另一个常见混淆：模型给某个答案 80% 的概率，不等于这类答案实测有 80% 的正确率。 预测概率需要校准才能有这样的解释；本轮没有把概率置信度当成已验证的正确率。

7. 为什么按 prompt 分组，又为什么不能重开旧留出

如果把同一道题的不同作者答案随机分到训练和验证两边，模型就可能靠题目内容或同题细节拿到较高分数。但隐藏测试题目是新的，这种验证会偏乐观。

GroupKFold 的规则是：同一 prompt 的所有文本必须待在同一折。验证时整道题目都没参与该折拟合，更接近我们真正关心的场景。

OOF 是 out-of-fold 的缩写：一条样本的预测，由没有用它及同题文本拟合的那个模型给出。把五折中分别留下的预测拼起来，才能对每条开发样本进行一次相对公平的评分。

旧留出已经用过一次。反复查看它，再根据结果修改方案，它就逐渐变成了开发数据，失去了原本的独立检查作用。因此我们保留它的历史，不再打开来选模型。

新建一个实验 ID、登记一份新预算，不会生成一个新的独立测试集。 当前 120 个 prompt 已被多次用于开发，所有 CV 与 bootstrap 结论都必须保留这个限制。Bootstrap 可以描述这批数据中的波动，不能抹掉多轮选模造成的乐观偏差。

8. 常用术语速查

术语在本项目里怎么理解
样本 / label一段文本是一个样本；它由哪个模型写的是 label（真实标签）
prompt写作题目；同题文本属于一个 group
特征 / embedding把文本转换成供分类器计算的一组数字
token模型读取文本时的小块；不严格等于一个词
pooling把多个 token 的表示汇总成一篇文本的表示；第二轮使用带 mask 的平均
冻结不更新编码器权重；仍然可以运行它提取特征
微调 / fine-tuning用任务数据更新已有模型的参数；需要新的训练和隔离方案
loss / 交叉熵训练时惩罚预测与标签的差距；下降不等同于验证BA提高
epoch / 梯度累积完整训练一遍训练折 / 合并若干小批的梯度后再更新一次参数
分类头 / head接在表示后面、输出 18 类分数的部分
LRLogistic Regression，逻辑回归；本项目用于多类别分类，不是预测连续数值的普通线性回归
n-gram / TF-IDF连续字符或词片段 / 根据训练文本中的出现频率为片段赋权
LinearSVC / margin线性支持向量分类器 / 用于比较类别的原始分数，不直接等于概率
softmax / 校准把分数归一化 / 检查和调整分数与实际正确率的关系，两者不等价
温度 / 嵌套验证用正标量调整分数分布 / 在外层训练集内部再划分校准数据，外层仍只做评估
融合 / 对照组合不同模型输出 / 帮助判断新步骤究竟有没有增益的比较对象
PCA用较少方向表示数据变化；所有拟合步骤只看训练折
协方差多个特征如何一起变化；高斯头用它衡量不同方向的不确定性
正则化 / 收缩限制估计过度追随有限样本的细节，让估计更稳定
fit / inferencefit 从训练数据估计参数；inference 使用已有参数做预测
batch一次一起处理的若干样本；本项目编码器提取 batch=4
CV / fold / OOF交叉验证、其中一份划分、各样本在未参与拟合时取得的预测
recall / BA某一类被认对的比例 / 各类别 recall 的等权平均
paired bootstrap对同一批 prompt 成对重采样，比较两个模型在相同行上的差异
数据泄漏让验证答案、真实分组或验证中学到的变换不恰当地进入训练或推理
claim / SHA256claim 记录实验是否执行及消耗次数；SHA256 用于核对文件字节身份，不证明模型有效

9. 三个可以亲手完成的小练习

练习一：指标为什么会“看起来很好”

在 HTML 的计算器里，让 A 全部答对、B 和 C 全部答错。先猜普通准确率和 BA，再看结果。然后把 B、C 各改成全部答对，观察哪个指标更直接反映少数类的改善。

答案：前一种情况普通准确率约 83.3%，BA 只有 33.3%。这个例子说明一个高总体分数可能掩盖类别短板，不是本项目的真实类别分布。

练习二：识别一次验证泄漏

假设 prompt P 的两条文本分别放进训练折和验证折，虽然 id 不同，这个划分是否适合本任务？如果先用全部开发数据拟合 PCA，再做五折，是否仍算严格的折内预处理？

答案：两者都不符合本项目的严格开发协议。第一种泄漏同题信息；第二种让预处理提前看到了验证特征。预训练且未受本任务数据更新的冻结编码器，与在本数据上拟合 PCA，是两件不同的事。

练习三：读懂一次“涨分但不提交”

第三轮比第二轮高了 0.8773 个百分点，为什么仍不提交？试着只看第 1 节和第 5 节写出三条理由。

答案：绝对 BA 与最低折表现不足；配对区间跨 0；只有 3/5 折改善且配对点增益低于要求。更完整的条件已在运行前固定，不能事后挑选其中一项来宣布通过。
