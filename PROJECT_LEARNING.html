Name That LLM：完整集成之后，怎样验证小改动

更新：2026-10-29。我们的正式最佳仍为 R12 V1 / 363188587 的 Public Score 0.654。队友 e651 为 0.651。外部 Roman V32 为 0.660，R14 已冻结该配方，但没有保存版本或正式分数。R15 仅完成本地算法入口和合成验证，还没有真实精度结果。

为什么这一轮固定完整集成

一个 SVC 分支提高，不代表加入几十种预测信号的完整方案也会提高。其它成员可能已经提供相同的信息，新的信号也可能改变原有正确答案。因此 R15 要固定同一份完整上游输出，只改变最后一个系数。旧 R6–R10 训练与搜索已经结束，本轮没有重复执行。

此前 Windows 阶段的详细学习记录保留在独立分支中：历史学习笔记。本分支不改写那些历史结果。

R15 想回答什么

R14 在完整融合后，用 37 个标点和排版特征微调类别分数。比如单双换行、成对引号和括号会一起出现；上游模型也可能已经利用这些信息。重复强化可能帮助识别，也可能把不确定但原本正确的答案推错，目前没有因果证据。

因此只登记一个候选：把末端排版改变量乘以 0.5。对照保持原强度 1.0，其它参数、成员和 ATLAS 覆盖保持一致。不在看到结果后再挑 0.25、0.75 或别的系数。

为什么现在还不能报提分

缺少完整集成的五折预测，以及每个训练依赖没有见过对应验证题目的证据。full-fit 模型已经用过这些题目，不能因为把预测数组命名为 OOF 就当成未见数据的预测。现有 ModernBERT/独立 SVC OOF 也不能代替完整集成。

旧 30-prompt 留出已经使用且受保护，继续封存。既定 120-prompt 开发范围可以按历史算法恢复；行序、标签顺序和 GroupKFold 折号都有冻结哈希，无需重新抽样。

两种“验证通过”有什么不同

本地工程验证：15 项合成测试通过，确认原强度公式与冻结上游一致、减半只改指定项、错误折绑定和错误尺度被拒绝。这些数据都是人工构造的。

本地预测验证：必须用真实、完整且隔离正确的五折预测计算 BA、18 类召回率和按 prompt 配对区间。本轮尚未开始，真实训练、编码器前向、官方标签评分和旧留出访问均为 0。

Kaggle 保存、正式提交、Public Score 和 private 结果又各是独立阶段。本轮这些新增计数全部为 0。R12 已完成的 0.654 不再称作等待出分。

一个容易忽略的尺度问题

上游 --save_lp 会把分数再除以总权重。虽然每行最大类别可能不变，分数之间的间隔会改变，排版算法的置信度门控也会改变。因此消融必须保存 _v38_before_hard 的原始尺度。R15 另外核对独立生成的原强度结果，防止输入虽合法却不代表同一基线。

当前交付与下一依赖

实际代码：CPU 重放。方案：预登记。缺失资产与最小补齐方式：完整集成 bundle 契约。实际结果：R15 报告。

后续只读查找已完成：公开的单次 LoRA24 OOF、182 文件的 nested validation cache 和 UltraBERT 五折 checkpoint 确实存在，但都未满足本轮完整 R14、原 120-prompt 划分和旧 30-prompt 排除条件。ATLAS 还明确记录使用全部 2699 条官方数据训练。没有把这些组件资产拼接后冒充完整 OOF，也没有启动评分。

源码另显示，部分融合系数和 Gaussian 温度来自上游 OOF/135-prompt 拟合。严格完整流程 OOF 还需要解决这些参数的训练范围；只重训基础模型不够。按当前成员拓扑，五个外折至少有 155 个神经 checkpoint/bundle 目标，可选 token-attention 最多另加 10 个；这是输出目标数量，实际训练任务还取决于可安全共享的阶段和内层验证。

具体证据见资产查找报告。最小重建预案先要求补齐源码、训练范围与 development-only 文本，再用最多 8 GPU-hours 试跑定标；完整重建提出 250 GPU-hours 总硬上限，必须由实测支持才可登记执行。当前没有启动这些任务，原 R15 单变量配置和停止门槛保持不变。

优先级 0 的新发现

已实际保存 S7、Instyle 和两个 token-attention 固定版本源码。源码可读不等于训练可立即重现：Instyle 把全部清洗后的外部行加进每个训练折，给 prompt ID 加 ext_ 也不能证明题目独立。EXTRA_W=0.5 仅被声明，没有用于训练权重；重建应以实际代码为准，并把修订另行登记。

恢复开发文本也有严格边界。旧 loader 虽然只保存开发行，却先读取并解析完整 train.csv；在“不碰旧留出”的要求下不能运行它。本轮实现了仅接收预先隔离导出的校验器，先检查来源审查，再核对原有行、文本和折哈希，找不到输入就停止。目前没有合格的 2159 行文本导出。

严格的融合验证需要在每个外折的 96 个训练 prompts 中再做五折，用内层预测拟合系数，之后才预测外层 24 prompts。旧 155 个目标只数最终外折模型，不包括这个代价；不能把它当作完整计算预算。新入口的 11 项测试使用人工数据，真实训练、前向、评分、旧留出读取仍为零。见 P0 报告和来源归档。
