2026-11-03，用户在聊天中批准：“Yes, run R21”。本任务只准备，交 Claude 审核和提交；后续 `net` 任务才可上传。以下为固定实验计划；本地合成验证不代表真实运行或门槛结果。

Claude 的两项必须修复：

1. **任何门槛不得依赖不可获得的完整集成 OOF**；采用相关的代理为经 pipeline Sinkhorn 后处理的 CPU 成员混合。
2. R19/R20 没有做 Sinkhorn；必须对每一验证折按 pipeline 对 test 的规则独立平衡，只用该折训练侧的先验。

## 假设及冻结条件

假设：v15 配置在经过 Sinkhorn 的 CPU 混合上优于 R16 配置。两组均只包含 SVC、TF-IDF LR、distort LR；排除 typography、ATLAS、GPU 和 COMP。这是多设置共同变化对公开配置的检验，并非单变量实验。

| 参数 | R16 | v15 |
|---|---|---|
| SVC pool | `nlm_pool_v5` | Open Pool v11 |
| extra | `nlm_matched_clean` | v11 按 `match_weight` 每类抽样，目标为 matched-clean 该类数的 2 倍，最多该类可用数；`random_state=0` |
| extra 权重 | 0.5 | 0.5 |
| SVC / TF-IDF / distort 权重 | 1.5 / 0.25 / 0.10 | 12 / 0.25 / 0.10 |
| Sinkhorn 强度 / target mix / sk_div | 0.45 / 0.35 / 1 | 0.30 / 0.35 / 1 |

R16 运行参数见 `r21-plan/analysis/r16_cells.txt:298-300,1949-1951`。v15 运行参数见 `r21-plan/analysis/areeb_cells.txt:392-394,2032-2052,2073-2077`：其命令行虽然写 1.5 / 0.45，但解析后覆盖为 12 / 0.30；`sk_div` 取默认值 1。extra 采样在原 notebook 于推理前全局进行（`areeb_cells.txt:2037-2046`），因此本计划先按原规则全局抽样，再对每折分别过滤 pool 和已抽样 extra，不在折内重新抽样。源代码无 CV 过滤：本实验额外应用 R19/R20 的外部答案余弦 ≥0.90 排除规则及规范化精确键排除，属于有意的验证隔离改动。R19 对 V11 的审计记录 flag true 0 行、空值 0 行（`docs/R19_PLAN_20261102.md:9`），因此 v15 全量读取与 R19 过滤在该输入上一致；运行时继续过滤并强制移除数为 0、空值为 0，否则停止。

每折的训练数据仅由其余 prompt 构成。对每折分别用训练侧标签计数加一得到先验，在三成员加权分数相加并按非零成员数除以 3 后计算概率，再执行 notebook 的 100 次列/行缩放及对数空间混合（`areeb_cells.txt:928-930,947-961`；`r16_cells.txt:838-840,857-871`）。2,159 行五折并非每折都能恰为 432 行，按实际冻结 fold_id 使用每折全部行，不能补齐或丢弃。

## 门槛与记录

采用 balanced blend 的 argmax，要求同时满足：balanced accuracy 差 ≥ +0.01；prompt 配对 bootstrap 95% 下界 > 0（seed 19，10,000 次）；至少 4/5 折严格改善；任何类召回下降不超过 0.05。另报告 SVC 单独与未平衡 blend 的数值，不作为门槛。通过后 v15 配置才成为后续仅重新加权轮次的已验证基线；失败则记录、停止、不调参。任何情况均不提交。

每折、每条件保存三个成员的 18 维逐行未加权 log-prob 或 decision、加权 blend、平衡输出、真值、fold、group、标签顺序、输入 SHA256 和版本，形成 `result.json` 与 `scores.npz`，允许无需重新拟合而重新加权。须明确 SVC decision 到 log-softmax 的转换，保持类别索引对齐。仅在全部折、数据身份、分数和元信息通过校验后才可宣称完成。

固定执行顺序：fold 0 至 4；每折先 baseline（R16）再 candidate（v15）；每个条件依次 TF-IDF、distort、SVC。这样时间不足时优先保留两条件的完整折。每个 `(condition, fold, member)` 成功后立即以同目录临时文件及原子重命名写入 `parts/<condition>__f<fold>__<member>.npz`，保存分数、原始行索引、输入哈希、配置哈希、内容校验值及阶段时间/RSS；随后原子更新 `progress.json`。监督器的 receipt 记录已完成单元数，部分结果绝不计算或报告门槛。进程恰在分片重命名和 progress 更新之间终止时，progress 可能少记一个单元，以已落盘分片和 receipt 计数为准。

`--run --resume-from <dir>` 仅供**日后另行明确批准的运行**使用，本次不启用；必须使用新输出目录及新的单次 claim。恢复时先校验全部现有分片的输入、配置、源码、运行时版本、分数内容和折行索引，任何不匹配或损坏均停止；只计算缺失单元，最终 `result.json` 列明恢复的单元。运行时版本绑定使跨环境恢复可能被拒绝，不能绕过该检查。

## 输入、预算与停止规则

计划附加私有 `zephyrpong/ntl-r21-scorebank-package`（开发 JSON SHA256 `1c9446efa6c8c477bd68448f1de212aadcc8dc90224b76728ec2f70e2ec2334f` 与脚本）、`crtproduction/name-that-llm-open-pool/11`、`dhruvtibarewal/nlm-matched-clean/3`；后者还提供 `nlm_pool_v5.parquet` 和采样计数所需的 `nlm_matched_clean.parquet`。无需模型权重；需要 numpy、pandas、scipy、scikit-learn、pyarrow、psutil。实际附件和输入 SHA 须在运行前核验，按文件名在 `/kaggle/input` 下发现，歧义或缺失停止。

预算：私有 Kaggle CPU notebook 最多 1 次 Save、墙钟不超过 9 小时、GPU 0、提交 0；可新建一个私有数据集。监督器默认在 8 小时 55 分钟触发墙钟或 CPU 停止，为复制 checkpoint 和 receipt 预留约 5 分钟，实际保存时间仍取决于平台。启动可用内存至少 24 GiB，进程树采样 RSS 上限 28 GiB；一次性 claim，失败保留 claim，不自动重试。成员和条件按顺序执行并释放内存；超过预算、数据或环境异常、输出不完整均失败停止。采样不能保证发现采样间的瞬时峰值。

R20 的两条件五折 SVC 实测 3.62 小时、峰值 21.45 GiB（`docs/R20_REPORT_20261103.md:1-3`）。仅供容量规划的粗估：读取/全局采样和五折过滤合计约 0.2–2 小时、RSS 约 2–12 GiB；十次 SVC 合计约 2–5 小时、RSS 约 15–28+ GiB；十次 TF-IDF LR 约 1–4 小时、RSS 约 4–28+ GiB；十次 distort LR 约 1–6 小时、RSS 约 4–28+ GiB；平衡与保存预计数分钟、RSS 主要受已有输入影响。这些区间除 SVC 的 R20 整体对照外均无实测依据，也不构成上界；尤其 distort 的词汇表未设上限。总耗时可能超 9 小时，任何阶段也可能超 28 GiB。运行时记录每阶段开始、结束、墙钟、CPU 和采样 RSS；资源不够时停止，不靠改配置或重跑跨过门槛。

## 限制

CPU 子集不能代表完整集成；已查看 R19/R20 的结果，开发集重复选择有偏；v15 与公开分数 57915690 的映射未证实；答案相似度过滤不能排除 prompt 级泄漏。旧 30-prompt holdout 不读取；不读取竞赛原始 CSV。CPU 成员和 Sinkhorn 均执行两份 notebook 的抽取源码；折内 train 先验和 scorebank 仅作为代理。Kaggle 环境包版本记录而不强制固定，输入哈希始终强制校验。`--smoke` 仅使用合成数据，正式 `--run` 留待后续授权的网络阶段，准备阶段不执行。
