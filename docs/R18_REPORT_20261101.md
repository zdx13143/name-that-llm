没有把这轮称为完整集成。adapter 内部的 BF16 重试仍沿用基线。

## V1 失败、边界复现与 V2 工程修复

V1 最终 ERROR，页面显示 282.5 秒、T4 x2；日志在 274.42 秒报告第一个
q14v5_f0 的 `Lifecycle.loaded` 中 `flat[indexes]` 越界。模型权重已经开始加载，
但还未合并 adapter 或 forward；仅有 before_load 事件，没有 loaded/released。
没有 preflight success receipt、placeholder 或正式提交。

新增指纹检查使用默认 float32 的 `linspace` 后转整数，大型参数末端 n-1 可能
被舍入成 n。只用 4 字节 CPU storage 的逻辑 view 和实际 Lifecycle.loaded，
稳定复现 `index 26214400 is out of bounds ... size 26214400`。旧 4x4 fixture
未覆盖此边界；这是新增检查代码的缺陷。Kaggle 异步错误栈未给出具体参数名称，
因此不声称已定位到远端某个具体权重矩阵。

修复采用 Python 整数乘除生成最多 64 个 int64 索引，并跳过空参数。实际 loaded
函数在 9 种人工尺寸（0 到 777,912,320）全部通过，底层 storage 每例仅 4 字节，
本地真实模型/GPU forward/比赛数据访问均为 0。默认 Python 无 torch 的首次
诊断命令失败，切换项目既有 venv 后完成复现；没有安装新软件。
