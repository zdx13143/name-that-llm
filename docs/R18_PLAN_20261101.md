In R16 `infer.py:l24_predict`, q14v5 and q8v5 each reuse one FP16 base across
five fold adapters plus a full adapter. Each adapter adds a rounded dense
delta and then subtracts it. FP16 addition/subtraction need not recover the
original weights. A triggered FP16->BF16->FP16 overflow retry can also propagate
rounding changes into the next adapter. Existing local receipts contain no
hidden-run logits or per-adapter measurements, so actual classification impact
is unknown.

The one prediction change is: load the same immutable pretrained base freshly
for each adapter, merge that adapter once, predict with unchanged pooling/head
math, then release it before loading the next. Remove unmerge; release GPU
hidden-state/module/weight references explicitly. Each adapter retains the
existing within-adapter overflow retry. This isolates adapters but does not
claim to remove within-adapter BF16 rounding or GPU kernel nondeterminism.

Keep all R16 models, 30 ordered input versions, coefficients, tokenizer rules,
head averaging, Gaussian/COMP/ATLAS calculations, and typography strength 0.5.
