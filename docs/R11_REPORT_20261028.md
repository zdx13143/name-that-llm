## Confirmed failure behavior and fix

The original complementary launch used a shell pipeline without a checked child return code. `infer.py` then caught missing, corrupt or misaligned complementary output and continued without it. ATLAS exceptions were also caught and skipped. Thus a successful-looking submission could represent a reduced ensemble rather than the intended full baseline.

This is a reproducible failure-path defect, **not evidence that it caused the existing 0.651 score**. The downloaded saved-run logs show `comp stack loaded (3157s)` and ATLAS `mixed at 0.1`. Those logs cover the three public placeholder test rows; they are not hidden-test logs.

[The separate R11 notebook](../notebooks/team_e651_r11_integrity.ipynb) now:

1. Invalidates old generated submissions and complementary files before baseline setup.
2. Checks child exit status and remaining wall-time budget; failed stages remove their declared outputs.
3. Writes complementary metadata with a fresh run ID, matrix hash, member names, weights and row coverage; validates these before fusion.
4. Requires the ten active base complementary members and, when grouped rows exist, the ten active grouped members. `lora24_public` and `tokattn_q35` remain excluded as in the observed baseline configuration.
5. Propagates ATLAS exceptions and rejects nonfinite final scores.
6. Checks submission columns, ordered IDs, row count and label set.

The original weights and numerical transformations are unchanged. The family gates remain unused: activating them is an accuracy hypothesis that this round cannot validate. The fusion temperature/member-count behavior is also unchanged.

The member manifest is a contract for the exact pinned baseline inputs, not a general validator for every upstream input combination. The source can discover `lora24_public` if an additional checkpoint is attached, but that checkpoint was absent in the observed V1 run. Such a newly present member (and its twin) is deliberately rejected as baseline drift; it must not be silently enabled or added to the accepted manifest. The suite covers this rejection. Preserve V1's pinned input versions when preparing any future full run.

## Accuracy boundary and next requirement

The baseline output inventory contains only three-row complementary predictions, not complete ensemble OOF. [The v5 dataset](https://www.kaggle.com/datasets/dhruvtibarewal/nlm-l24-adapters-v5) displays 54 adapter/head files and no fold manifest/OOF asset. An adapter name ending in `_f0` is insufficient to prove prompt exclusions; other ensemble components also use full-data fitted heads. The existing `--sim` path does not retrain all upstream components and cannot be relabelled as leakage-free complete-ensemble CV.

Therefore this report has no CV BA, per-class recall or score delta. Synthetic parity does not validate GPU numerical behavior, hidden-test runtime, or accuracy. No new GPU execution was performed, and the generated notebook is **not Kaggle-validated**. Stricter failure handling deliberately turns a degraded-ensemble submission into an explicit failure.
