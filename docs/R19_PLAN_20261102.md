## 验证集相似度控制及限制

比赛开发数据无 prompt 文本。每折对两池及 matched-clean，用该折所有验证答案构建相同的词 1–2 gram 哈希计数向量（2^20 特征、无符号哈希、小写、L2 归一化），删除与任一验证答案余弦至少 0.90 的外部行；0.85 至小于 0.90 的计数只作敏感性诊断，不调整阈值或筛选。各来源规则相同；候选池在此之前执行上述 Zbigniew flag 清理。阈值在任何 CV 前冻结。每折记录各来源排除数，匹配结果、维度或身份校验不符则停止。

此方法只能排除高相似答案，不能识别来自同一 prompt 但措辞不同的生成答案，也不能以外部池 prompt_key 单独反推缺失的验证 prompt。因而无法证明 prompt 级无泄漏，结果只能视为有这一局限的开发性比较，不能宣称严格无污染 OOF。外部池的 train-prompt 标记或数据集作者清理说明均不能弥补这一缺口。

## 协议和停止规则

五折按 prompt 分组，两个条件使用同一 SVC 单体 OOF；主指标 BA，报告 18 类召回和逐折差值。配对 prompt 分组 bootstrap 种子 19、10000 次，双侧 95% 区间。采用需同时满足 BA 提升 ≥0.01、下界 >0、至少 4/5 折改善、无单类召回下降 >0.05；不满足即停止，不调参。

本地 CPU 总预算 ≤4 小时（两条件各五折），GPU 0，记录内存峰值。输入哈希、折分组、相似度过滤和一次性原子 claim 验证失败、预算耗尽或资源不足即停止并保存回执。合成测试与极小冒烟不报告分数。`scripts/r19_overlap_audit.py` 只统计相似度；`scripts/r19_cpu_cv.py` 是真实 CV runner，实际运行前必须先由 Claude 完成本地 commit 并核验工作树。运行命令：`python scripts/r19_cpu_cv.py --run`。不得在本准备阶段运行该命令。
