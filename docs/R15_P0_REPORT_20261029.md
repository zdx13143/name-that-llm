## External-data exclusion: actual code evidence

In [Instyle](../reference_sources/r15_p0/instyle_v2.py.txt), lines 91-108 scan
five wildcard families: `ntl_extra_passages_claude.csv`, `gen_passages.csv`,
`ntl_generations.csv`, `ntl_proxy_generations.csv`, `ntl_generated*.csv`.
It applies finish filters, known labels, 30-300 words, deduplication and at
least 12 labels per prompt. These are content/coverage rules, not exclusions.

At lines 112-118, external prompt IDs receive `ext_`; no mapping to official
prompt identity is checked. Line 150 appends **every cleaned external row to
every training fold**. A different prefix does not prove a different prompt.
This is a missing exclusion mechanism, not proof that particular external
rows actually overlap; no external payload was read in this preparation.

`EXTRA_W=0.5` at line 86 is unused by sampling/loss; lines 187-190 use ordinary
plain + centered cross-entropy. A stricter `load_clean` is defined but unused.
Do not describe this source as implementing 50% class reweighting or that
stricter filter, and do not silently add them in a purported reproduction.

The frozen R14 main inference source also only removes normalized exact
held-out answer text in `--sim` (notebook lines 379-404, 424-461). That cannot
prove prompt-level independence of stage-one corpora or trained adapters.

Required external receipts before any source is admitted:

1. Exact dataset/version, file SHA256, generation/selection source and config,
   label mapping, source row digest and parent prompt lineage. No unrestricted
   `/kaggle/input/**` discovery; names alone do not identify data versions.
2. For official-derived prompts, preserve canonical official prompt identity.
   Admit only identities in the current outer/inner TRAIN allowlist. Reject
   all other/unknown identities, without inspecting protected text.
3. For independent prompts, require a reviewed provenance certificate showing
   independence from excluded official prompts and their reconstructions.
   Distinct IDs, `ext_` prefixes and exact-answer deduplication are insufficient.
4. Bind selected row digests/counts and rejected counts to each training stage,
   including stage one, vocabulary/PCA, classical heads and family gates.
   Deduplication or similarity thresholds learned from data must be trained
   inside the allowed envelope; do not use outer validation text to construct
   a new filter. Unknown lineage is rejected. A required source with no
   admissible membership blocks that member, rather than silently removing it.

No qualifying row-level external exclusion certificate was found in the
inspected sources. These requirements are not fabricated completed receipts.

The historical R2 cache does not store texts. The existing
`name-that-llm/scripts/windows_modernbert_dev.py:131-179` first hashes the full
CSV and uses `csv.DictReader` over it twice. `if index not in wanted: continue`
prevents retention but occurs **after parsing the row**. It is not acceptable
under this request's no-protected-content access boundary. It was not run;
neither train.csv nor the old cache arrays were opened or hashed here.

No pre-isolated export or previously certified byte-range index was located
by the bounded filename/source search. Therefore, local safe recovery from
the currently known files is blocked. Do not invent CSV byte offsets, use
shell filtering, or delegate the same full-CSV read elsewhere to call it safe.

The accepted route is a **preexisting, independently reviewed development-only
artifact**, supplied with metadata-only provenance and a review. An older
trusted exporter may provide such an artifact without reopening protected
content now. A new full-CSV extraction would change the current boundary and
is not part of this preparation. Nobody was contacted or sent data.

The [validator](../scripts/r15_validate_dev_export.py) accepts only fixed files:

- `development_export_receipt.json`: source kind, integer-zero protected
  content reads, `raw_official_csv_opened=false`, exact payload/evidence hashes,
  producer and all frozen identity/population fields.
- `development_export_review.json`: distinct reviewer, canonical receipt hash,
  evidence hash and `preisolated_development_source_verified` conclusion.

It checks sidecars before reading payload, bounds file sizes, prevents directory
escape, binds the consumed bytes to hashes, then verifies the original R2
row/text/fold hashes. The CLI also pins the canonical hash of the whole frozen

No real review or export was fabricated to make the gate pass.

## Fusion parameters: selected isolation design

The preparation selects a separately identified **strict nested producer**,
`r15p1-nested-dev120-draft`. It is not the exact R14 coefficient recipe and is
not admitted for training. The original R15 protocol/replay remain unchanged
and disabled. Settings are recorded in
[r15_p0_preparation_20261029.json](../configs/r15_p0_preparation_20261029.json).

For each of the five frozen outer folds:

1. Keep the existing 96 training / 24 validation prompts. Generate five inner
   GroupKFold folds within the 96 only, with `shuffle=False` and the original
   row order. This gives 25 inner folds across the five outer folds.
2. Produce inner held-out member predictions from dependencies fitted only on
   inner train. This applies to every task-trained stage, including stage-one
   weights, projections, vocabularies, Gaussian/readout parameters and external
   source selection. Averaging five adapters when four saw the inner validation
   prompt is not a valid shortcut. The internal checkpoint topology may require
   deeper splits and additional targets.
3. Fit/select learned COMP weights, Gaussian temperature/reduction settings,
   selected member/mixture weights, learned gates and thresholds using only
   those inner predictions and outer-train labels. Freeze the exact objective,
   constraints, candidate set, optimizer, seed and stopping rule **before
   GPU execution**. These exact source procedures are still missing; no new
   grid or invented substitute objective is registered in this P0 round.
4. Refit dependencies on the outer-train envelope using the selected settings.
   Use only its label prior. Predict that outer-validation fold as one batch;
   no cross-outer-fold transduction. Save raw pre-typography logits once and
   share member outputs and ATLAS selected/scored rows between both arms.
5. Fit typography on outer train and compare only strength 1.0 vs 0.5 on outer
   validation. Pooled outer results may be scored once after all producer
   receipts and the original fixed-replay budget gate pass. They may not be
   fed back to calibration, member selection or stopping decisions.

If a calibrated intermediate is later used as an allegedly OOF feature for
another learned stack layer, it needs its own cross-fitting; fitting and then
evaluating a meta-layer on the same OOF rows does not establish meta-layer OOF.
The outer fold remains the evaluation boundary. Architecture and recipe design
were chosen historically; even fresh isolated fits give descriptive evidence
on reused development prompts, not a pristine untouched validation set.

The old 155 required targets describe final outer-fold bundles only. A naive
five-inner-plus-final reconstruction would involve `155 * 6 = 930` top-level
target instances (up to 60 optional additions), **not a measured training-job
count or a revised budget**. Safe stage sharing may reduce work; deeper fits
may add work. The proposed 250 GPU-hour ceiling has not been shown feasible
for this nested design and cannot be released on the basis of the 155 count.
