# R25 preregistration draft — assignment with Gemini 3.7 score correction

**Status: frozen by user approval; implementation and synthetic tests only. No real evaluation has been run.** R25 will evaluate one primary candidate family on the existing development score bank. Its hypothesis is that a targeted Gemini 3.7 score correction can be combined with R24’s soft assignment while satisfying the existing per-class recall constraint.

R24 improved development BA substantially but failed its gate: one outer fold had no feasible inner-fold alpha, and overall `claude-fable-5` recall dropped by more than 0.05 versus R16. R22 improved Gemini 3.7 recall using a 3.8-to-3.7 prediction rule. R25 tests a score-level combination; it does not assume that either result will transfer.

## One primary candidate family

For each fold, compute `s` as the median strictly positive top-1 minus top-2 gap in its unmodified `areeb_balanced` scores. Stop if no positive gap exists or `s` is not finite and positive. For each row in that fold, set `z = (scores - row_max) / s`; every row retains its own fold’s scale, including within a cluster spanning folds.

Let `a` be `gemini-3.7-flash`, and let `b` be `gemini-3.8-flash`. Determine eligibility **once from the unmodified row scores**: `eligible_i = (argmax(z_i) == b)`, using NumPy’s first-index tie convention. Define

\[
z'_{i,c}=z_{i,c}+\beta\,\mathbf{1}[c=a]\,\mathbf{1}[\mathrm{eligible}_i].
\]

Apply R24’s assignment to `z'` for estimated clusters of size 12–18:

\[
\underset{y}{\operatorname{maximize}}\quad
\sum_i z'_{i,y_i}-\alpha\sum_c \max(0,n_c-1).
\]

Clusters outside that size range use independent `argmax(z')`. At `alpha = 0`, **all** rows use independent `argmax(z')`; at `beta = 0`, the rule reproduces R24 for the same alpha and clustering.

The restriction to rows whose original argmax is 3.8 keeps the correction close to R22’s targeted intervention and avoids directly boosting 3.7 on every row. It is still **not identical to R22**: with assignment, the bias can affect the joint solution and other rows’ assigned labels. Even at `alpha = 0`, equality at the threshold follows `argmax` tie handling, whereas R22 switches only when the raw 3.8–3.7 gap is strictly less than lambda. An unrestricted 3.7 bias could also pull rows whose original winner is not 3.8; it is outside this primary family.

**No fable bias gamma is included.** Fable was identified through the R24 result; adding a targeted parameter would introduce another data-dependent choice and enlarge the search. The joint selector may choose a smaller alpha, but this is not guaranteed to repair fable. If the fixed grid cannot meet the recall constraint, R25 fails rather than adding gamma or relaxing the constraint. The Gemini correction and the decision to examine this combination are themselves informed by reused development results.

## Grid and deterministic selection

Freeze the 16 combinations:

- `alpha ∈ {0, 0.5, 1, 2}`
- `beta ∈ {0, 0.5, 1, 1.5}`

R22 often selected raw-score `lambda = 1.0`; R24 fold scales were approximately 1.0–1.2, so the corresponding normalized gap is roughly 0.83–1.0. The beta grid brackets that reference with zero and a few coarse values. This is a scale rationale, not an equivalence claim or an estimate of the best beta.

Use R24’s exact slot-based solver. For positive alpha, resolve equal optima by the lexicographically smallest class-index vector in original row order, with R24’s documented floating-point tolerance. For alpha zero use independent NumPy `argmax`. For parameter selection, maximize pooled BA among feasible combinations; on exact BA ties choose smaller alpha, then smaller beta. Use the same fixed score-column order throughout.

For each outer fold:

1. Generate predictions for every fixed `(alpha, beta)` over whole estimated clusters without using labels. Cluster members may span folds; report their count. Candidate predictions use the same pair across the whole cluster when that grid point is evaluated.
2. On the other four folds pooled, compare each grid point’s per-class recall with R16 on those same rows. It is feasible only if no class drops by more than `0.05`; use the R24 numerical tolerance of `1e-12` for this selection check.
3. Select the feasible pair with highest pooled BA and the tie-break above. Apply that pair’s precomputed predictions to the held-out fold.
4. If no pair is feasible, record the failure and **fail the gate**. Do not substitute an infeasible pair or manufacture a complete primary BA from fallback predictions.

Concatenate the five held-out predictions only if all five selections succeed. This is cross-fitting over a fixed OOF bank, not fully nested model training: upstream models or priors for inner scores may have used outer-fold labels. Label-free clustering uses all development texts, and a cross-fold cluster can couple rows’ assignments.
