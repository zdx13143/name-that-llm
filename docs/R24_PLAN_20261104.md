# R24 preregistration draft — 2026-11-04

**Status: frozen as amended; implementation and synthetic testing only, no evaluation has been run.** R24 will make one local CV decision using a single prespecified candidate family: a soft duplicate-label penalty within **estimated** prompt clusters. The chosen strength will be cross-fitted. No other variant has adoption authority.

The hypothesis is that some duplicate predictions within a prompt can be corrected by using the near one-example-per-model panel structure. The soft penalty permits duplicates when the scores favor them, which is important because estimated clusters can merge unrelated passages or split a true prompt. Its strength is normalized to the score scale, making transfer more plausible than R22’s fixed numerical lambda. Transfer to the full ensemble remains unvalidated.

## Scope and fixed inputs

- Use the R21 five-fold, prompt-grouped OOF score bank: 2,159 development rows, 120 groups, 18 classes, three CPU members.
- Fixed `scores.npz` SHA-256: `85a4a8b7faf931a9d02dd4e6b1a3082487bd8e5aabb96b0498358a835d0c2393`.
- Fixed `development.json` SHA-256: `1c9446efa6c8c477bd68448f1de212aadcc8dc90224b76728ec2f70e2ec2334f`.
- `development.json` contains 2,159 `texts`, so the proposed CPU-only clustering is feasible from the admitted development export. Texts are used only in memory for clustering; do not print or export passages.
- Validate hashes, row alignment, 18-class mapping by name, finite scores, group/fold consistency, and the presence of all classes in every fold. Bank `row_index` is a positional index; development `row_index` contains strictly increasing source-row IDs.
- No raw competition CSV, protected 30-prompt holdout, Kaggle commands, new model fits, Saves, or submissions.

## Primary transformation

1. Start with the saved `areeb_balanced` scores, which already include the v15-recipe Sinkhorn operation. Cluster all 2,159 development texts together once, label-free, preserving row order; apply assignment to whole clusters, including clusters spanning folds. Record the number of cross-fold clusters. Each row uses its own outer fold?s selected alpha.
2. Reproduce v15’s content-word TF-IDF clustering on that fold’s texts: `sublinear_tf=True`, English stop words, `min_df=2`, `max_df=0.05`, cosine similarities, capped average linkage, cap 18, and threshold `0.15`. Preserve source row order and deterministic tie handling. If TF-IDF raises the same empty-vocabulary/pruning `ValueError` as v15, use singleton clusters and record the fallback.
3. For each fold, let `s` be the median of the positive row-wise top-1 minus top-2 score gaps. Require `s` to be finite and positive; otherwise stop. Divide scores by `s`; row-wise additive constants do not affect the decision.
4. Apply the following rule only to estimated clusters of size **12–18**. All smaller clusters retain their independent argmax. For each eligible cluster, choose labels maximizing

   \[
   \sum_i z_{i,y_i}-\alpha\sum_{c=1}^{18}\max(0,n_c-1),
   \]

   where `z` is the normalized score and `n_c` is the number of cluster rows assigned class `c`. Implement this exactly with assignment slots: the first slot for each class has no penalty, and each additional slot costs `α`. Resolve equal optima deterministically using a documented lexicographic row/class rule.
5. Fixed grid: `α ∈ {0, 0.25, 0.5, 1, 2}`. Define `α=0` explicitly as independent row-wise argmax, including ties. This is the no-assignment option. No R22 pair rule or additional balancing is part of the primary candidate.

The penalty is invariant to a common positive rescaling and row-wise additive shifts, but it is not invariant to changes in relative class scores, cluster quality, or the score distribution’s shape.

**Typography boundary:** the bank has no Bayesian typography evidence. In deployment, construct `_safe_logits = _v38_before_hard + gate * typography_evidence` first, then cluster the actual test texts and apply the frozen R24 rule to those `_safe_logits`, immediately before the final parquet write. Thus R24 CV measures the rule on pre-typography three-member proxy scores, while deployment would use post-typography full-ensemble scores. Passing CV does not validate that interaction or prove a full-ensemble gain.

## Selection and fixed comparisons

For each outer fold:

- Generate cluster assignments separately for each of the five folds without labels. For each `α`, calculate predictions independently within each fold.
- Select `α` using only the **other four folds**, pooled for BA and class recall. Compare each option’s per-class recall with the fixed R16 balanced baseline on those same four folds.
- An option is feasible only if no class recall drops by more than `0.05`. Among feasible options, maximize pooled BA; on exact ties choose the smaller `α`. If none is feasible, mark that outer fold as a selection failure and **fail the adoption gate**; do not fall back to an infeasible option.
- Apply the selected `α` to the untouched outer fold. Concatenate the five outer-fold predictions for the single primary result.

This is cross-fitting over a fixed OOF score bank, not fully nested model training: upstream models and priors for inner-fold scores may have used outer-fold labels. The clustering itself uses all development texts but no labels; cross-fold cluster members influence each other?s assignments.

Two comparisons are fixed before evaluating R24:

1. **R16 gate baseline:** `r16_balanced.argmax`, mapped by class name. Preserve the R22/R19 gate: BA gain `≥ 0.01`; paired prompt bootstrap 95% lower bound `> 0`; at least 4 of 5 fold BA gains `> 0`; and no class recall drop exceeding `0.05`. Also require candidate BA `≥ 0.509118` and reproduce the R21 unadjusted v15-versus-R16 BA gain of `0.029147` to six decimals.
2. **R22 no-regression comparison:** reproduce the already preregistered R22 cross-fitted predictions using its frozen rule and outer-fold lambdas `[1.0, 1.5, 1.0, 1.0, 1.0]`; verify the recorded result and BA `0.523284` to six decimals. Require R24 BA to exceed the **unrounded reproduced R22 BA** by at least `0.005`, and the paired prompt bootstrap 95% lower bound for R24 minus R22 to be `> 0`.

For both paired comparisons, resample true prompt groups with replacement, seed `19`, 10,000 replicates, and use the 2.5th percentile as the lower bound. Evaluate fixed concatenated predictions; do not reselect `α` within bootstrap replicates. Stop if input checks or reproduction fail. Adoption requires **both** comparisons and every selection check to pass.

After a pass, select the deployment `α` once using the same grid, feasibility rule, and tie-break on all five development folds. Record it separately from the five outer-fold choices. This full-development selection is for a prospective package; it is not another unbiased evaluation.

## Secondary diagnostics — no adoption authority

Report estimated cluster-size distribution, singleton/fallback counts, ARI against true development groups, cluster purity/completeness, changed-row counts, predicted class counts, per-fold BA, class recalls, and confusion summaries. True groups are used for diagnostics and bootstrap only, never as inputs to primary assignment.

A hard Hungarian assignment using **true** groups may be reported once as an explicitly labeled oracle grouping diagnostic; it is not deployable and is not a guaranteed mathematical upper bound on BA. The one 17-row panel must be handled as incomplete.

Stronger Sinkhorn balancing and a combination with the R22 pair rule are **not in the primary grid**. If reported, they must be separately labeled exploratory, receive no adoption authority, and cannot trigger a new R24 gate, grid change, or submission. A future balancing study must rerun the extracted Sinkhorn code from raw `areeb_blend` separately for each validation fold, using that fold’s training-side priors only. It must not rebalance the already balanced bank scores or assume the same operation can be inserted after `_safe_logits` without a defined deployment mapping.

## Interpretation limits

The three-member bank is a proxy for the deployed full ensemble; the bank lacks typography and may differ in score distribution and component coverage. The v15 sim audit also found pretrained component provenance and external-data overlap risks, so ordinary sim output is not automatically leakage-free full-ensemble OOF evidence.

The same 120 development prompts have informed multiple rounds and this hypothesis. Cross-fitting and the prompt bootstrap do not remove that cumulative selection bias, uncertainty from upstream training, or parameter reselection. A pass supports a bounded R25 experiment, not a claim of independent generalization. The public v15 score is `0.666` for submission `57915690`; R23 submission `57979553` was recorded as pending and its overwritten pair rule cannot validate lambda.

Each row uses its own fold scale even inside cross-fold clusters. Centering each row is immaterial.
- For equal optimal assignments, choose the lexicographically smallest class-index vector in original source-row order. Objective comparisons allow floating-point summation error of `8 * machine epsilon * max(1, abs(optimum), n * max(abs(z)), n * alpha)`; near-equal objectives within that bound are treated as ties. Alpha zero is independently defined as row-wise NumPy argmax, including ties.
- Full-dev alpha selection is performed only after both gates pass; failure of any outer selection is a gate failure and no deployment alpha is returned. The result is exclusive-create and a resource or reproduction failure stops without publishing a result.
- Peak RSS is sampled every 0.1 seconds by the resource watchdog; its reported peak is a sampled value, not an operating-system high-water mark.
